# StampFly_Basic400 — 学生向けの基礎飛行モデル

`StampFly_PIDBlock_FlightTest400.slx` をコピーし、宙返り（Flip）を除いたモデルです。プロジェクト直下の **[StampFly_Basic400.slx](../../archive/aircraft/StampFly_Basic400.slx)** を使います。`Basic`は基礎版、`400`は制御の実行周波数400 Hzを表します。元のPID版は変更していません。

## 基礎版で学ぶ流れ

センサー取得 → 校正・補正 → 姿勢・高度推定 → 操縦指令と離着陸の判断 → PID制御 → 4モーターへの配分、の順に読みます。飛行状態は **校正 → PARKING（待機）→ FLIGHT（離陸・飛行）→ LANDING（着陸）→ PARKING** と進みます。

| 維持した機能 | 内容 |
|---|---|
| 通常の操縦・離着陸 | JoyStickの中央液晶ボタン、角度／角速度モード、自動／手動高度 |
| 7個の専用PID | 高度、鉛直速度、Roll／Pitch角、Roll／Pitch／Yaw角速度 |
| 推定とセンサー処理 | BMI270、下向きToF、電池、姿勢・高度推定、校正・フィルター・リセット |
| モーター出力 | 400 Hzの更新、150 kHz指定・8 bitのPWM |
| 観測と記録 | 光学フロー・磁気を含む50 Hzのログ、JoyStickへの40 Hzの状態返信 |

光学フローと磁気は観測用です。水平位置保持は行いません。

## 削除と簡素化

- `OfficialFlipSequence` Chart、FLIP状態とその遷移、離着陸・モード確定ChartのFlip条件を削除しました。
- 高度・姿勢指令のFlip分岐、Flip中の制御有効化・リセット・センサーフラグ・LEDの処理を削除しました。
- Flipの位相・完了・角速度を保持するメモリー、AHRSリセットとのOR、完了直後のモーター出力保持を削除しました。
- 関連するバス項目、入出力ポート、配線を減らしました。角度リセットは通常の制御リセットと共通にし、前周期へ渡す情報も通常制御に必要なものに絞りました。

**Flip用のスティック押し込みは、Stick Modeにかかわらず無視されます。** 基礎版の`BasicJoystick400`は通常操縦の指令だけをモデルへ出力します。中央液晶ボタンによる離着陸と、左右前面ボタンによるモード変更は維持しています。

元のPID版との互換性のため、共通の低レベル受信コードには従来のパケット解釈が残っています。基礎版はFlipイベントを取得せず、モデル内にFlip用の状態・信号・制御経路を持ちません。

## MATLAB／Simulinkの画面から開いてビルドする

1. MATLABの **［ホーム］→［開く］** で `StampFly_Official.prj` を開き、**「機体モデル（基礎版）」** を選びます。直下の `StampFly_Basic400.slx` をダブルクリックしても開けます。基礎版は単独で初期化できます。
2. **Ctrl+D（モデル更新）** を押し、診断ビューアーにエラーがないことを確認します。
3. [READMEの専用チャンネル設定](../../README.md#???????????????)に従い、自分の機体・JoyStick・受信機を同じCHへそろえます。機体は **JoystickCommand400 → JoyStickInput400 → BasicJoystick400 → Channel** と、`code/+official/LogTransport50.m`の送信初期化の2箇所を変更します。
4. **Ctrl+E → Hardware Implementation → Hardware board settings → Build options** で **Build action = Build** にします。**Code Generation → System target file = ert.tlc**、**Generate code onlyが無効**であることを確認し、**［適用］→［OK］**、保存の順に進みます。
5. **［アプリ］→［Embedded Coder］→［C コード］→［ビルド］**、または **Ctrl+B** を押します。ビルドログの保存先で **`StampFly_Basic400.bin`** の生成を確認します。

機体と送信機の準備、COMポート選択、書き込み、アプリ、初回飛行の手順は[README](../../README.md)にあります。基礎版の保存済みモデルは実モーター出力が有効です。書き込み・机上確認ではバッテリーとプロペラを外します。

PIDを自分で編集する場合は **FlightControl400 → TakeoffHoverControl400** の高度・姿勢・角速度制御を開き、`DedicatedPID`のパラメーター画面で係数を変更します。[READMEのPID編集例](../../README.md#??????)を参照してください。別フォルダーへプロジェクトをコピーして変更する場合も、対応するビルド設定を使えるよう機体モデル名は`StampFly_Basic400.slx`を保ちます。

`scripts/model_edit/create_basic_flight400.m`は、このコピーを構築した履歴です。完成済みモデルへの初回セットアップとして一括実行する必要はありません。

## アプリとファームウェアの区別

既存の`StampFlyIMUApp`と受信機モデルをそのまま使えます。ログはBuildID **1401**、基礎版のFirmwareRevision **1601**です。既存形式の互換性を保つため、従来のFlip項目2箇所はゼロを送ります。

`firmware/logging400/`などの既存BINはコピー元の版です。基礎版は `build/basic400/firmware/StampFly_Basic400.bin` から開発機へ書き込み、同じBINを **`firmware/basic400/StampFly_Basic400.bin`** に保存しました。保存BINのチャンネルはCH 3です。自分専用のCHを使う場合は、上記の手順で設定して再ビルドしてください。

| 確認 | 結果 |

| Flipの残存と接続 | 保存済みSLXと生成されたモデルのC／HでFlip参照ゼロ。未接続ポート・線とStateflowの検査で問題なし |
| モデル全体の更新・コンパイル | 成功 |
| ESP32-S3向けビルド | 成功。7個のPID、2.5 ms周期、PWM設定を確認 |
| MATLABプロジェクト | 基礎版と関連ファイルを登録し、「機体モデル（基礎版）」を追加。12項目のチェックがすべて成功 |
| 実機への書き込み | COM4の開発機にアプリ領域を書き込み、980,272 byte全体のdigest照合に成功 |
| USBでの起動確認 | 10秒間、3種類のログを各501フレーム受信。CRCエラーなし、Revision 1601、待機モード3、適用PWMゼロを確認 |
| 実飛行 | 2026-10-16にユーザーから飛行試験成功（「完璧です」）の報告。飛行ログは未取得 |

比較は保存済みセンサー・操縦入力の再生で、機体の空力を含む閉ループ飛行シミュレーションではありません。通常出力の一致は、実機飛行の確認を代替しません。

実飛行の結果はユーザーの報告に基づきます。飛行ログを取得していないため、この試験の高度・姿勢誤差や制御周期などの数値評価は行っていません。

コピー元からの診断バス3項目の信号名不一致と、`NormalizeDuty`のsingle精度への量子化の警告は残っています。今回の比較とビルドはこれらの警告を含めて成功しています。
