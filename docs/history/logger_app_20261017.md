# 2026-10-17 ロガー表示・制御設定の整理

ユーザーから保存先選択、ゼロの高度補正グラフ、診断線の重なり、XY開始・終点、状態順、データ名表示、実PIDに対応する設定画面を依頼されました。

旧飛行操作と高度PI適用は無効化されており、現在の7 PIDへ反映されませんでした。現在の制御パラメータ画面は実ブロックの係数を読み、編集値をPC側のモデルへ反映します。モデルの保存・再ビルド・書き込みは別操作です。成功飛行版1804の係数や保存モデル・機体BINは、このアプリ改善で変更していません。

通常パケットの高度補正・スロットルは0.1刻みの量子化があり、最新2記録のうち1件は補正が全点0、もう1件は0／0.1だけでした。SFIXの`BaseDuty`・`ThrustCommand`には細かい制御値が記録されています。履歴は同じSequence・Time・BuildIDの補足を結合し、共通推力差とモーター平均を表示します。未記録のPID個別P/I/D項は表示しません。

診断は上下のOFF／ON帯を項目ごとに離し、状態切替の縦線と区別します。飛行状態の機体コードは維持し、表示だけ初期化→校正→待機→飛行制御→着陸に写像します。各グラフへファイル名・ライブ受信元を付け、XYへ最初／最後の観測点を追加しました。

保存先は履歴一覧と自動・手動記録で共有します。記録中の変更は次の記録から反映し、開いているファイルを移動しません。CRC正常の記録をライブ表示の重複・時刻判定で取りこぼさないよう、記録と描画の判定も分離しました。

実ログではSFIXの行番号が補足の欠落・他種類の混在によって不等間隔となり、`matfile`の直接索引が失敗するケースを確認しました。連続する小区間で読み出して同じキーの行へ対応付ける方式に修正し、未記録値はNaNを維持します。診断グラフの再描画で残っていた非表示ハンドルの線も明示的に削除します。
