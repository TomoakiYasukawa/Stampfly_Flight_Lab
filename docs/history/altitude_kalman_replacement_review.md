# AltitudeKalmanを標準Kalman Filterへ置き換える検討

2026-10-16、MATLAB R2026b。対象は `StampFly_IMU400/AttitudeAltitudeEstimation400/AltitudeKalman`（SID 2236）。**置き換えは可能です。ただし、標準ブロックの設定に加え、現在と同じ周期の推定値を取り出す計算と、モード別の保持・リセット処理が必要です。** 現行も線形Kalmanフィルターなので、推定の基本方式は共通です。この文書は検討結果であり、飛行モデル・ファームウェアを変更していません。

## 現行の推定器

保存済みモデルのMATLAB Functionを確認しました。実装は [kalmanStep.m](../../code/+official/kalmanStep.m)、[AltitudeKalman400.m](../../code/+official/AltitudeKalman400.m) と対応します。

内部状態は `x = [鉛直速度; 高度; 加速度バイアス]` の3状態です。入力は、ToFから作った高度 `alt` と、オフセット補正・低域通過フィルターを通した加速度 `az`。出力端子の順序は **高度・速度・バイアス** なので、内部状態の順序と入れ替えます。

実測周期を `h = dt` とすると、現在の予測・観測モデルは次の行列で表せます。

```matlab
A = [1 0 -h;
     h 1  0;
     0 0  1-0.01*h];
B = [h; 0; 0];
C = [0 1 0];
D = 0;
Qeff = diag([0.01*h^2, 0, h^2]);
R = 0.004^2;
x0 = zeros(3,1);
P0 = 100*eye(3);
```

毎周期、`xp = A*x + B*az`、`Pp = A*P*A' + Qeff` を計算してから、**その周期のToF高度で補正し、補正後の推定値を直ちに出力**します。高度の予測に `0.5*h^2*az` の項はありません。バイアスには `1-0.01*h` の減衰があります。最初の移行ではこれらを維持するのが比較しやすい方法です。

高度だけの観測でも、`h > 0` では3状態の可観測性があります。ToFが十分更新される前提で、速度・バイアスも推定できる構造です。数学的に推定可能であることは、実機での推定精度やToF欠測時の安定性を保証するものではありません。

## 標準ブロックの設定と出力時刻

[Kalman Filterの公式資料](https://jp.mathworks.com/help/control/ref/kalmanfilter.html)と、インストール済みR2026bの `ctrlSharedLib/Kalman Filter` を確認しました。ライブラリは **Control System Toolbox → State Estimation → Kalman Filter** です。System Identification Toolboxにも同じブロックがあり、C/C++コード生成とsingle型に対応します。

公式資料の離散時間ブロックは、現在の観測で現在の事前推定値を補正し、`u[n]` で次の事前推定値へ進めます。そのため、上記の `A/B/C/D` をそのまま指定して **「現在の測定値 y[n] を使用して xhat[n] を改善」** を選ぶだけでは、現行の「現在の加速度・dtで予測した後の出力」と時刻が合いません。dtが一定でも入力の扱いが1周期分異なり、実測dtが変動すると行列の適用時刻も問題になります。

現在の `Qeff` は高度方向のプロセスノイズがゼロ、すなわち `Qeff*C' = 0` です。この性質を使えば、標準ブロックに渡す観測行列を変えて同じ更新順序を表現できます。

| 設定・端子 | 移行候補 |
|---|---|
| 時間領域 | Discrete-Time |
| サンプル時間 | 0.0025 s（400 Hz）。実測dtは別途、行列の生成に使用 |
| 現在の測定値を使用 | on |
| モデルソース | Input port、状態3・既知入力1・観測出力1 |
| 入力u / 観測y | 現行の `az` / `alt` |
| A / B | 上記の `A(h)` / `B(h)` |
| **ブロックに渡すC / D** | **`C*A = [h 1 0]` / `C*B = 0`** |
| G / H | 既定の `I` / `0` |
| Q | 「時不変Q」を解除し、上記の `Qeff(h)` を端子入力 |
| R / N | `single(0.004^2)` / `zeros(3,1,'single')`、時不変 |
| 初期推定値のソース | Input port。X0・P0を外から与える |
| 推定器外へ渡す状態 | **`A(h)*xhat_current + B(h)*az`** を計算し、高度・速度・バイアスに分ける |

この構成では、標準ブロックの現在推定値は前周期側の状態に対する補正値です。最後の行列演算で、現行と同じ時刻の3状態を取り出します。標準ブロックの内部では同じ値が次周期に向けて保存されます。必要に応じて、外へ渡す状態の共分散も `A*Z*A' + Qeff` として確認できます。

固定行列と固定ノイズをすべてダイアログに記入すると、標準ブロックは**定常ゲインのフィルター**を選びます。現行は初期共分散・待機時の共分散リセットを含め毎周期ゲインが変わるため、単純な固定行列設定では離陸前後の動作が変わります。入力端子から実測dtに応じた行列を与え、時変共分散を計算する構成が候補です。

上記の変換について、100組の状態・正定値共分散・dt（1～6 ms）で、現行の行列式と公式資料の式をdoubleで比較しました。最大差は状態 `8.9e-16`、共分散 `2.7e-15` でした。これは**式の対応を確かめた計算であり、実際のSimulinkブロックの比較、singleでの誤差評価、リセット比較、生成コードの検証は未実施**です。記録はローカルの `logs/altitude_kalman_review/timing_mapping_algebra.json` にあります。

高度へのプロセスノイズや `0.5*h^2` 項を後で追加すると、この簡単な変換の前提も変わります。その場合はDやノイズ相関まで再検討します。

## モード・待機リセットで維持する動作

現行の待機リセットは、状態をすべてゼロにする一般的な処理と異なります。

| 条件 | 現在の動作と移行上の注意 |
|---|---|
| モード0・1 | 予測も観測補正も停止し、状態・出力を保持する |
| 最初の処理周期・待機モード3への遷移 | フィルター更新全体を1周期省く |
| parkingReset | 共分散を `100*I`、公開出力をゼロにするが、**内部状態xは残す** |
| PARKING中の継続周期 | parkingResetが継続し、毎周期リセット後に予測・補正する。単発リセットではない |
| モード入力 | 既存のフィードバック遅延を経たモードを使う。遅延を維持する |

標準ブロックの **Enable端子は観測補正だけを停止**し、予測は進めます。モード0・1や初回の更新省略には、外側のEnabled Subsystemなどで**更新全体を止める処理**が必要です。

リセット時のX0には保持した内部状態を、P0には `100*I` を与える候補です。ゼロにする公開出力と、保持する内部状態は別に管理します。更新停止中に起きたリセットも扱う必要があります。Resetの **Level hold** は非ゼロの間リセットしますが、**Level** は非ゼロからゼロへ戻る周期にもリセットします。PARKING解除時の余計なリセットを避けるため、Level holdを候補にして初回省略・保持との組合せを単体比較します。

## 単位・センサー前処理・数値処理

| 考慮点 | 判断 |
|---|---|
| 加速度の単位 | `az` はg単位で、その数値を現在の速度積分へ直接使用している。SI単位として整合していない。**初回移行で9.80665を掛けると推定特性も変わる**ため、単位の是正は別の変更として扱う |
| 加速度の座標系 | 現在はオフセット補正した機体Z成分を使う。IMU Filterの姿勢で地球座標の鉛直へ回転し、重力を除く処理は高度推定には入っていない。大きく傾いた飛行の改善候補 |
| ToFと高度 | mmをmへ変換した下向き距離を使用。制御に使う高度はここで姿勢による傾きを補正していない。床面・反射・測定範囲外にも依存する |
| 観測周期 | ToFの取得は約25 Hz。最新値の保持・外れ値処理・低域通過フィルターを経た高度を、推定器は400 Hzで繰り返し観測する。新着フラグは推定器へ入っていない |
| Q/Rの意味 | Rは4 mm相当の標準偏差の二乗。保持・平滑化された連続観測は独立でなく、実測ノイズと調整値の再評価余地がある。初回は値と観測周期を維持し、新着時だけ補正する改善は別途調整する |
| singleの数値差 | 標準ブロックは共分散の数値安定性を考慮した計算を行う。現行の展開式と丸め順序が異なるため、bit単位の一致を前提にしない。高度だけでなく速度・バイアス・PID/PWMへの影響も比較する |
| コード生成・処理時間 | ブロックは対応するが、当該構成のESP32-S3ビルドは未実施。数値端子・定数をsingleに統一し、行列サイズを固定する。生成コードのサイズと400 Hz全体の処理時間を確認する |

現在の整理済みIMU400は、ユーザーから「飛行試験OKです。」との報告があります。USB机上の6,000周期では平均1.611 ms、最大2.546 ms、2.5 ms超過3回でした。したがって、置き換え後の計算量を無条件に増やせるとは判断できません。飛行ログはまだなく、飛行中の処理時間は数値評価していません。

## 推奨する進め方

最初は**標準ブロックへの移行だけを行い、現行の入力前処理、単位、Q/R、観測周期、モード処理、PID、Supervisor、ログ形式を維持**する方針を勧めます。標準ブロック化には、行列・ノイズの役割を授業で説明しやすくし、共分散の計算を標準機能へ任せられる利点があります。係数の生成、出力時刻の変換、モード処理を小さなサブシステムにまとめ、Kalman Filter自体の設定を追える構成が適しています。設定を置き換えるだけで推定精度が向上するわけではありません。

実装に進む際は、飛行成功モデルのコピーで次を順に確認します。

1. 実際の保存済みAltitudeKalmanと標準ブロック構成を同じ入力で比較。初回、dt変動、待機継続、着陸・再離陸、モード0/1、ToF保持・外れ値・欠測を含める。
2. singleで高度・速度・バイアスの差を評価し、その差が既存PIDとPWMに与える影響を確認。数値差の許容値はこの結果を見て定める。
3. モデル更新・ESP32-S3コード生成・ビルドを確認。既存のフィードバック遅延を維持し、直接フィードスルーによる代数ループがないことを確認。
4. USB机上で出力・起動・リセットと400 Hz全体の時間を計測。その後、飛行ログを取って高度保持と再離陸を比較。
5. 移行が確認できた後、SI単位、姿勢を使った鉛直加速度、ToF傾き補正、新着時のみの観測補正とQ/R再調整を、個別に検討。
