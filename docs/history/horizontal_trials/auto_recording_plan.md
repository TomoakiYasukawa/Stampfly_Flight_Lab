# StampFlyIMUApp 自動飛行記録の変更方針

既存の App Designer 形式（`.m` と `.xml`）を維持し、受信した飛行状態から記録を開始・保存する。操縦・離着陸指令は送らない。

2026-10-17の実装前方針です。実装後の状態番号、遅延パケット・時刻リセット処理と検証結果は[調査結果](20261017_fall_review.md)にまとめています。

- 機体が飛行（2）または着陸（5）になった最初の通常／指令補足パケットで開始する。接続時に既に飛行中でも記録する。
- 離陸前2秒の受信パケットを保持し、開始時に同じファイルへ書く。待機に戻った後1秒も保存する。
- 通信途絶・機体再起動・アプリ切断を、正常着陸と区別して保存する。
- 通常、指令、センサー、水平補足を受信順に残し、既存の時刻・Sequence・CRC・欠落集計を維持する。受信できないパケットは生成しない。
- 飛行中は定期的にMATへ書き出し、記録開始ボタンの押し忘れを防ぐ。従来の手動記録は机上確認用として残す。
- 状態判定とファイル管理を `code/+imu/FlightRecorder.m` へまとめ、アプリは受信・表示・終了処理から呼ぶ。
- 閉じる際に記録を保存し、確認タイマーを停止・削除する。

参照: matlab-build-app の `references/editing-guide.md`、`references/app-designer/agent-guide-shared.md`、`references/app-designer/agent-guide-plaintext.md`、`references/uifigure/callbacks.md`、`references/timers.md`。

検証: 実機操作を含まないパケット再生で、離陸前・飛行・着陸・停止、複数飛行、途中接続、通信途絶、再起動、補足の先着、対象外BuildID、保存エラーを確認し、既存表示・手動記録テストも実行する。
