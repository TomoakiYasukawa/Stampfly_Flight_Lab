# 水平補助の処理時間・通信の調整記録

**最新の状況は[落下・記録・Z速度の調査](20261017_fall_review.md)を参照してください。** 以下は水平補助1801の途中段階の机上測定で、1802修正後の実機検証ではありません。

2026-10-17のUSB机上測定です。機体はバッテリー・プロペラを外した状態で、飛行指令を送っていません。各JSONの`Passed`はログ・待機出力の確認だけを表し、周期の合否は`TaskTimingSummary.AllObservedTasksWithinBudget`で別に判定しています。

| 段階 | 全タスク平均／最大 [µs] | 2,500 µs超過／測定周期 | CRCエラー |

| 最初の水平補助 | 1,910.9／3,223 | 1,274／24,000 | 1 |
| 64 bit差分の試行 | 1,946.65／3,026 | 1,001／8,000 | 0 |

全測定でスケジューラーの欠落tickは0でしたが、一部のタスクが周期を超えているため、これらを周期検証の合格とはしていません。USBでは実際に途中で短くなったフレームも確認し、`Serial.write`の部分書き込みを保持・再送する修正を追加しました。

高さ60 cmの申告に対応する初期記録ではToFも約60～62 cmでしたが、フローのSQUALは11～24で閾値25を下回りました。その後の取得値はToF約17～22 cm、SQUAL約120～135でした。後者を60 cmでのセンサー確認結果として扱っていません。

通常利用の説明と最新の検証記録は[水平補助](../../horizontal_control.md)を参照してください。ここにある中間JSONは当時の結果です。`CaptureFile`の生ログはGit管理外です。
