# horizontal-hold: 実装手順案

更新: 2026-10-17。状態: **実装・モデル検証済み**。[構成](horizontal-hold-architecture.md)

実装は`code/+horizontal`、現行モデルのHorizontalMotionEstimationとHorizontalControlへ保存済み。OFF回帰、実7 PIDを含む閉ループ、9条件のずれ、生成MEX、アプリ・ログを検証した。以下は当初の段階計画を残す。実機による軸・倍率校正と飛行性能確認はモデル検証とは別に実施する。[現行の設定と検証記録](../../../horizontal_control.md)

## Phase 0: 座標・観測を確定する

この検討結果を確認して実装を開始する段階で、次を決める。未確定の符号・倍率のまま水平フィードバックを有効にしない。

1. 機体の前・右・下、PMW取り付け、IMUの軸、Quaternionの回転規約を確認。前後・左右への既知移動と機体回転で、速度観測と角度出力の符号を照合する。
2. フロー倍率を両軸で校正。静止回転によりフローとジャイロの時間差・回転補正残差を測り、中心からのセンサー位置も測る。
3. 模様／照明／高さ別のSQUAL・フルshutter・外れ値・ToF更新間隔を記録。速度有効フラグ、位置基準、解除理由、閾値を確定する。
4. 名前付きHorizontalMotionバスを[局所X,Y]で定義。50 Hzスナップショット、50→400 Hz角度保持と前周期配分飽和を確定する。

完了条件: [試験計画](horizontal-hold-test-plan.md)の座標・倍率・回転・観測健全性試験が成立。センサー仕様と初期閾値表を更新。

## Phase 1: 制御に接続せず速度を記録する

OpticalFlowSensorの生取得を使い、HorizontalMotionEstimationで400 Hz区間を集計し、50 Hzの速度・相対位置と有効性を作る。既存の表示専用FlowDistance50は比較に使い、新しい制御でその出力を微分しない。

モデルの主経路へ推定バスを明示して配置する。ログはGoto／Fromで分岐。制御目標・観測時刻・品質区間・ジャイロ積分が後から検証できる項目を追加し、受信機／アプリの対応版も揃える。既存フレームを黙って再定義せず、版と追加項目を明記する。

完了条件: 有効な既知移動で推定が一致し、制御OFF時は既存出力・Supervisor・7 PIDに差がない。現行ファイルのSHAとビルド結果を記録。

## Phase 2: 速度ループを有効にする

HorizontalControlに目標生成・速度PI・制限をまとめる。位置Pはまだ無効にし、中立を速度ゼロ、操作を速度目標とする。AttitudeControlのRoll/Pitch目標の手前で選択し、Yaw・高度・モーター経路は既存の制御を使う。

離陸・着陸・解除・復帰を明示する。Run／Reset／低推力／配分飽和による積分制限を接続し、モデル内の日本語説明・端子名を整える。

完了条件: MILの停止・移動・Yaw・欠測・飽和・切替試験、コード生成比較、実機周期評価。実飛行は速度制御の低速から確認する。

## Phase 3: 停止位置の保持を追加する

HOLDの位置PとBRAKE終了時の位置目標記憶を有効にする。MOVEで古い目標を解除すること、Yawだけでは目標を回さないこと、欠測復帰で基準を更新することを確認する。

完了条件: 外部観測を使う位置保持・移動後停止・再移動の試験。位置と速度の両ループを同時に強く調整せず、速度が成立してから位置Pを上げる。

## 水平制御の次段階: 磁気Yaw補正・方位保持

ユーザー確認により、水平制御と分けて進める。磁気の機体校正、モーター電流・周囲金属の影響、傾斜補償、更新時刻・欠測を確認した後、Yaw推定補正と方位保持を仕様化する。

既存YawRatePIDは残し、その前段に方位誤差から角速度目標を作る経路を加える。Yaw操作を妨げず、中立時に目標方位を保持する。磁気による基準の更新で水平の保持目標が跳ばないように座標・リセットを管理する。現行Yawの時間変化が水平試験の目標を妨げる場合は、水平の動作範囲を広げる前にこの段階へ進む。

自動飛行はさらに後の別段階とし、今回の目標生成と速度制御の境界を再利用する。

## Phase 4: 配布用に整える

機能単位の配置、最小限の階層、2軸の順序、日本語コメントと設定説明を最終確認する。READMEに補助中のスティック動作、有効条件、解除表示、Simulinkでの調整・ビルド手順を簡潔に加え、比較と試験記録は履歴へ置く。

推定／制御はモデルと同梱コードだけで動く構成にする。追加依存、受信機版、ログ版、ファームウェアとCHの確認を記録してGitLab／GitHubへ反映する。

## Simulinkから調整する入口

実装時はHorizontalControlの設定画面に速度・加速度・傾き上限、位置P、速度PI、補助の有効化をまとめる。HorizontalMotionEstimationに倍率、品質、高さ、経過時間と速度平滑化をまとめる。校正前の推定を制御へ接続しない。

調整は **ブロックをダブルクリック → 係数を変更 →［適用］→ Ctrl+D → 保存 → Ctrl+Bでビルド**を基本とする。実機への反映は既存[セットアップ](../../../setup.md)の［ビルド、展開、起動］に従う。比較用の値と検証ログを残し、設定をスクリプトの手編集だけに依存させない。
