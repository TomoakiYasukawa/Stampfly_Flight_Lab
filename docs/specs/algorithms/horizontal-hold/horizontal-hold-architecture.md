# horizontal-hold: 構成と制御式

更新: 2026-10-17。状態: **実装・モデル検証済み**。[要求](horizontal-hold-system.md)、[実装と設定](../../../horizontal_control.md)

## 機能のまとめ方

| 配置候補 | 内容 | 周期・状態 |
|---|---|---|
| HorizontalMotionEstimation | 時刻付き区間集計、品質判定、回転・距離補正、速度と相対位置 | 集計400 Hz、推定50 Hz |
| FlightControl／TakeoffHoverControl／AttitudeControl／HorizontalControl | 操作状態、位置P、速度PI、制限、角度目標選択 | Systemは400 Hz。位置P・PIは観測Updatedで50 Hz更新。不要な外側ラッパーは作らない |
| AttitudeControl | 既存Roll/Pitch目標の直前で水平補助を選択 | 400 Hz。既存角度・角速度PIDへ接続 |

推定と制御の境界は名前付きバスで渡し、PositionLocal2／VelocityLocal2の順は[X,Y]を保つ。演算は2軸ベクトルでまとめる。フローのセンサー軸→機体軸、機体→局所の変換だけを境界に置く。ログへの枝は既存Goto／Fromを利用する。

## 推定

1. **400 Hz区間集計:** 前回フロー読み出しから今回までのcount差分、角速度積分、実測区間時間、品質・更新状態をまとめる。50 Hzへは同じ窓のデータを一括で渡す。現在のTotals2を差分化するだけでは区間内の低品質カウントを除けない。
2. **回転補正:** センサー取り付けに応じた軸行列・符号と校正係数でcountを画像の角変化へ変換し、対応する角速度積分を差し引く。PMWとIMUは別取引で読み出すため、同じ400 Hzでも内部遅延は別に測る。
3. **距離補正:** 有効で時刻の分かる下向き距離と姿勢で水平面への高さを求め、区間中央へ合わせる。新しいToFがない周期は経過時間と変化量を評価した保持を使う。初期段階で大きな鉛直運動・傾きの窓は採用しない。
4. **速度・位置:** 補正した角変化×斜距離÷実測区間時間を機体の画像速度に換算する。姿勢・鉛直速度で床面へ投影し、局所座標で速度を平滑化する。位置は平滑化前の速度を積分する。欠測でValidを落とし、無効な値をゼロ速度としない。

小傾斜・中央取り付け・平面近似では、現行の仮符号を使った式は次の形になる。`C`はcount/rad、`Δθ`はフロー窓と同じ時間の角速度積分[rad]、`h`は有効な床上高さ[m]。

```text
ΔsForward ≈ h (−ΣΔcountY / CY − ΔθPitch)
ΔsRight   ≈ h ( ΣΔcountX / CX + ΔθRoll)
vBodyXY   ≈ [ΔsForward; ΔsRight] / Δt
```

**この符号は現行ログ実装の仮定であり、機体で確定済みではない。** PX4のpixel_flowは機体軸周りの画像回転で、StampFlyの生countと同じ符号契約ではない。既知の前後・左右移動と純回転の試験をPhase 0の必須条件にする。

大きな傾き・上昇下降では床平面への射影モデルを用いる。センサーが中心からずれている場合は、`vSensor = vCenter + ω × rSensor`を補正する。Yawによる画像回転の残差も実測する。初期は小傾斜の有効範囲を定め、未検証の一般化を制御へ持ち込まない。

フローの400 Hz逐次値は量子化が大きいので、初期制御は50 Hzの平均速度を使う。低域フィルター状態と位置積分は無効区間で停止し、復帰時に新しい区間から初期化する。飛行セッション間で位置・時刻・目標を引き継がない。IMU加速度を使う速度予測やEKFは、遅延・欠測が実測上の問題になった場合の次段階とする。

## 目標生成

中立校正済みスティックをデッドゾーン外で再正規化し、円形の最大速度制限を使う。Roll/Pitchスティックの符号は実際の前進・右移動と一致させる。

```text
MOVE:  vTargetLocal = RHeadingToLocal · vStickBody
BRAKE: vTargetLocal = [0;0]
HOLD:  vTargetLocal = normLimit(KpPosition · (pHold − pEstimate), vMax)
```

目標速度の変化は毎回 `||ΔvRef|| ≤ aRefMax Δt` に制限する。局所座標で制限するため、移動中のYawで指令が急変することも抑える。BRAKEで停止条件が続いた時点に`pHold=pEstimate`とする。HOLD→MOVEでは位置目標を解除し、古い位置へ戻す成分を加えない。Yawだけの入力ではpHoldを変更しない。

目標生成の出力は局所座標の速度[m/s]とし、速度PIが生スティックや手動状態を直接解釈しない構成にする。将来の自動飛行では軌道の予定速度と位置誤差から同じ速度目標を作り、水平PIを再利用する。自動モードと目標源の選択は別段階で仕様化し、現在の実装範囲には追加しない。

## 後段のYaw補正との境界

今回の水平制御は現行のYaw角速度指令とIMU Filterを使う。磁気のYaw推定補正と、方位誤差からYaw角速度目標を作る方位保持は後段で追加する。速度観測・速度指令・位置積分・傾き指令が、常に同じ機体→局所の回転を使うことを前提にする。

一定の方位オフセットは局所座標の向きを変えるが、共通の変換を使う相対的な速度抑制には磁北への一致を要求しない。時間とともに変わる方位誤差は、積分位置と現在の速度・傾きの関係をずらすため、現行Yawのずれを合成入力と実ログで評価する。実機のYaw旋回によるフロー残差やレバーアームの影響も別に確認する。

磁気補正を後で追加した場合の初期化・リセット・推定基準変更は、局所位置、保持目標、速度PI状態の座標管理へ通知する。基準全体を変更する場合はそれらを整合して変換するか、新しい基準で保持を再開する。保持目標を残したまま座標の向きだけを飛ばさない。

## 速度PIと傾きへの変換

```text
eVelocity = vRefLocal − vEstimateLocal                     [m/s]
aRequest  = KpVelocity · eVelocity + iVelocity              [m/s²]
iNext     = iVelocity + KiVelocity · eVelocity · Δt         [m/s²]
aLimited  = normLimit(aRequest, aMax)                      [m/s²]
aBodyXY   = RHeadingToLocal' · aLimited                    [m/s²]
```

KpVelocityの単位は1/s、KiVelocityは1/s²、KpPositionは1/s。初期は位置に積分項、速度に微分項を置かない。制動が不足した場合は目標速度の加速度フィードフォワードを別途評価し、初回から必須にしない。

一般的な機体FRD（前・右・下）、Roll正＝右側が下、Pitch正＝機首が上、鉛直加速度ほぼゼロの小角度近似では、次が負帰還になる。

```text
RollTarget  ≈  aBodyRight / g
PitchTarget ≈ −aBodyForward / g
```

前へ流れた場合は前進加速度を負にし、機首を上げて減速する。右へ流れた場合は左向き加速度を作り、左へ傾ける。最終変換は合成傾き・角速度・目標変化を制限する。現行ミキサーは正Roll補正で右モーターを減らし左を増やし、正Pitch補正で前を増やし後ろを減らす形である。**モデル内のAngles・IMU Filter座標とこの物理定義を一致させるアダプターはPhase 0で検証する。**

既存FlightOutputsは推定器EulerのRoll/Pitchを交換し、Yawを反転して180°ずらしている。推定器の生QuaternionをBodyToLocalRotationとみなさない。一般回転の軸交換をEuler角の入れ替えだけで済ませず、取り付けとframe/point規約を含む回転行列で整理する。

## 飽和・リセット・解除

- 加速度、合成傾き、最大速度、目標変化率を制限する。対角操作は軸ごとではなくベクトルの大きさを制限する。
- 速度PIは条件付き積分と上限を使う。制限にさらに押し込む誤差成分では積分せず、戻す成分は許可する。角度・配分飽和も積分停止へ反映する。配分結果は1周期遅延で返し、同時刻の代数ループを作らない。
- 観測無効、Run=0、Reset、低高度、低推力、待機では積分更新を停止する。OFF／再有効化では位置・速度目標を作り直し、PIをゼロまたは連続な加速度へ追従初期化する。
- MOVE↔BRAKE↔HOLD間は健康な同一セッションなら速度PIを保持し、一定の機体偏りを補正する。位置目標だけを必要な遷移で更新する。
- 補助角度と従来角度の選択は0～1の重みと角度変化制限で移行する。解除中に水平観測は使わず、操縦入力は従来角度へ反映する。復帰は観測安定＋中立で行う。

## 実行とメモリー

| 状態・境界 | 保持方法・初期値 | 同時刻入力への依存 |
|---|---|---|
| フロー／角速度区間 | 400 Hzの離散状態、初期合計0、前時刻未設定 | 今回サンプルを含む窓を確定後に公開 |
| 400→50 Hz観測 | 同じ400 Hzタスク内で8周期の完成窓を公開、Updatedを1周期だけ出す | 非同期タスクを増やさず、完成した窓だけ使う |
| 速度平滑化・位置 | 離散状態、最初の有効速度／位置0で開始 | 有効な今回速度を使用。戻りは次周期 |
| 速度PI | Unit Delay相当の離散積分状態、初期0 | 今回誤差を使用、更新状態は次周期 |
| 50→400 Hz角度 | System内部で加速度目標を保持し、400 Hzで混合・変化率制限 | 最新の完成した加速度から姿勢目標を作る |
| 配分飽和→PI | Unit Delay、初期false | 前周期だけを参照 |

連続系のMemoryで遅延を代用しない。固定サイズsingleのベクトル、uint32の時刻・カウンター、boolean状態を使い、動的確保や追加のブロッキング読み出しを作らない。50 Hzへ分けても8周期ごとの最大負荷は増えるため、実測で2.5 ms制約を評価する。

## API・規約の確認状況

MATLAB System、型付きBus、BusSelector、Unit Delayを使い、新しい必須製品は追加していない。固定サイズsingleの型・次元は全モデル更新と生成コードで確認した。軸の正規直交変換は[実装解説](../../../horizontal_control.md)のとおり。モデル・ソース上の帰還符号は実7 PIDを使う閉ループ試験で確認し、実センサーの取り付け・倍率・遅延は実機で別に確認する。最初の調査資料は[証拠](horizontal-hold-review-evidence.json)に保存している。

実装の推力逆変換は既存の軸交換後の`Rz(heading)*Rx(controlRoll)*Ry(controlPitch)`に合わせ、`Roll=atan2(aRight,g)`、`Pitch=atan2(-aForward*cos(Roll),g)`を使う。速度の投影には水平近似の高さではなく斜距離を使い、`height=range*R(3,3)`を有効高度の判定に使う。
