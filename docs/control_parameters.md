# 制御パラメータの変更

アプリの **［制御パラメータ］→［モデルから再読込］** で、現在の`Stampfly_Tx.slx`から実際の係数を読みます。以前の飛行速度・高度・旧高度PIの欄は現在の制御に使われていなかったため、7個のPIDと水平P/PIの設定へ置き換えています。

表の値を編集し、**［モデルに反映］** を押すと、PCで開いているモデルの該当ブロックへ反映されます。**モデルを保存 → Ctrl+D → 再ビルド → 書き込み** で機体へ反映します。アプリに表示した値はPC側のモデル設定で、機体から読み出した係数ではありません。未保存のモデル側の設定も読み込みます。

USBでリアルタイム受信している間も［モデルから再読込］を使えます。処理中は制御パラメータ操作だけを無効にし、作業ウィンドウを表示します。受信データはキューへ保持し、モデル操作が終わると解析・描画を再開します。処理中に閉じる操作をした場合は、モデル操作と記録保存が終わってから終了します。

**現在の係数を機体へ反映するには再ビルドが必要です。** 以前の再ビルドなしの変更は、旧高さ調整用の9係数をTUNE／SFP1通信で受け取る経路でした。現行モデルにはその受信ブロックがなく、7個のPIDと水平P／PIへ接続されていません。旧コマンドを送るだけでは現行係数を変更できません。再ビルドなしの調整を復活するには、モデル・機体ファーム側へ現行係数の実行時受信とPIDへの接続を追加する必要があります。今回のアプリ修正では機体ファームを変更していません。

MATLAB Runtime版ではSimulinkモデル編集ボタンを無効にします。モデルの読み書きにはMATLABとSimulinkを使ってください。

## PIDの形式

7個ともSimulinkのDiscrete PID Controllerを **Ideal形式** で使います。表示値はブロックのP/I/D/Nと同じです。

| 表示 | 意味 | 従来の係数との対応 |
|---|---|---|
| P | 全体のゲイン | Kp |
| I [1/s] | 積分係数 | 1/Ti |
| D [s] | 微分時間 | Td |
| N [1/s] | 微分フィルター係数 | 1/(Eta × Td) |

Ideal形式はPを積分・微分にも掛けます。Parallel形式のKi/Kdをそのまま入力しないでください。I=0で積分、D=0で微分を止められます。Nは正の有限値を入力します。

| 行 | 入力→出力 | モデル内の場所（FlightControl → TakeoffHoverControl以下） |
|---|---|---|
| 高度 | 高度誤差→鉛直速度目標 | AltitudeControl → AltitudePID |
| 鉛直速度 | 速度誤差→共通推力補正 | AltitudeControl → VerticalSpeedPID |
| Roll／Pitch 姿勢 | 姿勢誤差→角速度目標 | AttitudeControl → RollAnglePID／PitchAnglePID |
| Roll／Pitch／Yaw 角速度 | 角速度誤差→モーター配分補正 | BodyRateControl → 各RatePID |

**［選択PIDを開く］** で`DedicatedPID`の設定画面を開けます。Simulink画面で係数を変更した場合は、アプリで再読込してから編集します。

## 水平位置・速度

位置Pは停止位置からのずれを速度目標へ変換し、速度PIは速度誤差を水平加速度目標へ変換します。微分項は使いません。単位・上限も表に表示します。

アプリから扱うのは位置P、速度P/I、移動速度上限、速度目標の加速度、補正加速度上限、積分上限、加速度変化率です。観測品質・補助の開始高度・切替時間は[水平補助の説明](horizontal_control.md)にある各ブロックから設定します。

係数を変えただけでは機体へ送信されません。最初に現行値を記録し、変更した係数が分かるモデルを保存して比較します。Revision 1804の実飛行結果は保存された係数・機体BINに対する結果です。
