## Aircraft execution and invariants

- ESP32-S3 Series (Arduino Compatible), `ert.tlc`, fixed-step discrete **0.0025 s / 400 Hz**, single-tasking. Receiver **0.01 s**. Tested R2026b / Arduino support package 26.2.3.
- Main graph: IMUSensor → SensorCorrection → AttitudeAltitudeEstimation → FlightControl → MotorWrite. OfficialFlightSupervisor is at root. Named Goto/From provides logging. HorizontalMotionEstimation is at root; horizontal control is inside AttitudeControl.
- Baserate is pinned to **CPU1** at task creation through `__wrap_mw_osThreadCreate` in `src/official_scheduler.cpp`. `ARDUINO_RUNNING_CORE=1` by itself did not pin the Simulink task. Keep task-specific pinning, GPTimer wrappers, and corrected cross-core idle age reads. **Do not disable watchdogs to claim a timing fix.**
- ToF/magnetic/battery acquisition and transport have separate CPU0 tasks. A block at 50 Hz is not automatically a separate CPU task. See docs/cpu_tasks.md.
- `code/+official/TickStart400.m` selects link wrappers using the generated model name. Current step wrap is **`--wrap=Stampfly_Tx_step`** with matching `__real_Stampfly_Tx_step` / `__wrap_Stampfly_Tx_step` in C++. A future rename must update both or timing/section measurement fails. Preserve historical profile branches used by saved older models.
- Runtime section probes deliberately wrap I/O without changing generated computations. SFTASK measures complete step; SFTIMING stops at an in-model point and excludes tail work. Treat all-task timing separately from log-integrity Passed.
- Sensor g→m/s² gain at altitude estimator boundary and rising-edge parking reset were essential corrections. Do not revert to continuous reset during waiting or compare them as presentation-only changes.
- Raw lower ToF is **slant range**. Display and horizontal projection apply tilt correction. Altitude PID/legacy estimator still receives slant range and body-Z acceleration; full world vertical projection and altitude-loop tilt correction are not implemented.
- Motors: FR, FL, RR, RL; 8-bit output, configured150kHz. Current saved model allows output; USB-only/battery removed is not permission to send flight commands. Do hardware actions only within current authorization.
- Seven **Ideal** PID blocks: altitude, vertical speed, roll/pitch angle, roll/pitch/yaw rate. P=Kp, I=1/Ti, D=Td, N=1/(eta*Td); P scales I/D terms too. Horizontal position P and velocity PI are before attitude/rate PID. Keep units and saturation/anti-windup.
- DataLogger edits **host model** expressions and leaves them unsaved. Current aircraft tuning requires **save → update → build → flash**. Old TUNE/SFP1 route accepted nine height parameters, but its receiver is absent/unconnected to current seven PID + horizontal controls. Do not promise runtime tuning or silently restore obsolete controls.

## DataLogger behavior and performance

- Preserve R2026b App Designer `.m`+`.xml`, AppId **`6045714e-c100-4972-8d8f-120b58fc45dc`**. XML owns layout/wiring; use AppDesignerAgentInterface for code/save and actual loader validation. - APIinspect callback text in the installed toolkit was found to strip leading chars incorrectly in this session; use actual saved code when checking callback preservation. `inspect.Properties` contains `{Default,Access}` where Default is MATLAB expression text; `addProperty` expects **native values**, not expression strings. Runtime tests are necessary; loader validation alone won't detect wrong default types. Empty typed-expression distinctions require care.
- AppId was kept through rename. Constructor uses `matlab.apps.App`; maintain all generated background code. Rename is not reason to rebuild task plumbing.
- Receive timer fetches bounded65536B, completes then waits20ms. Byte parsing normal budget15ms with adaptive35/50/80ms backlog budget; offset buffer avoids repeated head deletion. Live display completes then waits100ms (~10Hz); render only selected Monitor tab and defer if receive backlog.
- Busy guards prevent receive parse, model operation, live render and history render reentrancy. Model reads queue received bytes; close request waits for model work and ordered saves. Ensure error/cancel/empty-folder paths end AppActivity and release guards.
- History requests keyed by generation/path/mode/file signature. Changing selection invalidates pending older results even if new selection is cached. On Monitor tab, read/analyze only; draw history on History tab. First toolbar/zoom/pan preparation is deferred. Empty folder finishes activity and shows no records.
- History MAT-add feature was removed. Delete selects next older item, else previous at oldest. Multi-delete stays within selected paths and protects in-flight saves. Legends use explicit handles/names; **latest preference is fixed northwest** (earlierbest request superseded). No duplicate “表示データ” title line; one filename header. XY start/end legends use endpoint seconds independently.
- Monitor top: accel/gyro/mag/motor4columns; bottomToFleft,3Dright; tight margins while retaining titles/axes/units.
- Mesh remains9,740triangles/4,778vertices. `hgtransform` moves body+helper axes. Cache title, pose, floor bounds. FloorXY blue; YZ/ZX green packed in one NaN-separated line from bounded10s buffers. Projection bench16.26→16.68ms (+2.6%); later3D optimize15.67→11.91ms (~1.32x). Don't downsample geometry without evidence/visual validation.
- LiveTimeAxes fixes axes limits and translates line data for scrolling, maintaining raw XData/time. Updating axes limits every frame was the dominant graphics cost (~296ms vs44ms line-only on this PC). Explicit non-live updates return to ordinary axes to preserve exact bounds.
- Processes pool starts at app launch (new2workers). Next save/read restarts if expired and shows popup. License absent/threadpool/creationfail→synchronous fallback; retry cooldown60s. Do not use threadpool for unsupported `matfile` I/O. GUI graphics stay client-side.

## Tooling and session discipline

- Do not close user MATLAB, stop unknown workers, discard unsaved SLX/app, overwrite logs/backups, or write hardware during a purely local cleanup. Teams was explicitly off in this session; don't reactivate from copied history. Git integration/commit/push was deferred until user saw completion.
- On Windows, the running DevAI/Codex launch process and inherited MCP helpers can hold the project's root directory even after MATLAB is closed. Do not terminate the user's DevAI/Codex session or remotely close its handles. Move the contents (including .git) to the explicitly requested sibling folder and verify there; the old empty shell can be removed after the session releases it. Start the next DevAI/Codex task from the new folder. Any delayed deletion must check that the old folder is empty and that the new project marker exists; never delete recursively.
- Isolated MATLAB Engine queue is suitable when desktop MCP is stale. Every runner start needs a **new queue directory**; otherwise old jobs reexecute. `action:quit` shuts down only that isolated engine. Keep job JSON structured and avoid shell interpolation.
- Independent Engine may lack Java; use Python/PowerShell SHA256 instead ofJava security hashing. Installed toolkits aren't runtime requirements; initialize SATK only for tests/migrations that need it.
- App Designer API script path was `USERPROFILE/.matlab/agentic-toolkits/matlab/skills-catalog/matlab-app-building/matlab-build-app/scripts`; don't copy personal toolkits into this project. Preserved maintenance scripts can have outdated environment assumptions; update scoped copies before running.
